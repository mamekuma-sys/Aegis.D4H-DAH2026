## 관측과 정책 매핑

- Broker가 전달한 실제 TCP 목적지 profile은 `6/8080`과 `6/9000`이었다.
- `8080`에서 기존 L1 fixture와 같은 `helper-box:8080/secret` SSRF, 대체 내부 주소의
  canonical SSRF, `/config?file=...flag` traversal 요청이 관측됐다.
- 당시 정책은 동일한 세 규칙을 `6/8082`에만 적용해 해당 요청을 ACCEPT했다.
- `defender-2026-08-21-p1r1-8080-hotfix`는 세 정밀 규칙의 scope에 `6/8080`만 추가했다.
  HTTP가 아닌 `9000`에는 적용하지 않았고, 광범위 휴리스틱은 SHADOW 상태를 유지했다.
- P1-R2에서 `9000` SatDiag gRPC로 flag 2개가 탈취됐다. 후속 bundle
  `defender-2026-08-21-p2r3-graphql-satdiag`는 `TailDiagnosticLog…/flag`와
  `ExportDiagnosticBundle` command-injection(`;echo` / `${FLAG}`)을 `6/9000` ACTIVE로
  차단한다.
- R1 캡처에서 flag 문자열은 발견되지 않았으므로 그때는 관측되지 않은 공격 부류를
  ACTIVE로 승격하지 않았다.
