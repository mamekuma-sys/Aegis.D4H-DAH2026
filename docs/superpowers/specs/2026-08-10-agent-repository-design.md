# Aegis.0xD4H 본선 에이전트 저장소 설계

## 상태

- 결정일: 2026-08-10
- 결정: 에이전트 중심 저장소 + 초기부터 본선 인터페이스 준수 + 외부 스켈레톤 통합 시험장
- 팀: Aegis.0xD4H
- 책임자: 팀장 이경준

## 목표

예선 보고서의 공격·방어 아이디어를 본선 규격의 두 Docker 이미지로 발전시키되, 대회 운영용 스켈레톤 전체를 제품 저장소에 복사하지 않는다. 공격 담당자와 방어 담당자가 독립적으로 개발하고, 팀장이 공통 계약과 통합 결과를 검토할 수 있는 구조를 만든다.

## 설계 원칙

1. 최종 산출물은 공격 이미지와 방어 이미지 두 개다.
2. 스켈레톤은 제품 코드가 아니라 본선 인터페이스 예제이자 로컬 통합 시험장이다.
3. 인터페이스 적합성은 개발 마지막이 아니라 첫 커밋부터 자동 테스트한다.
4. 공격과 방어 사이에 런타임 공용 패키지를 만들지 않는다. 두 이미지는 독립적으로 빌드·실행되어야 한다.
5. 예선 보고서의 시나리오는 전략적 가설로 사용하며, 본선 취약점이나 관측 가능 데이터를 미리 단정하지 않는다.
6. 예선 소스는 검증된 알고리즘의 참고 구현이다. 합성 이벤트 생성기를 실제 공격기로 오인하지 않는다.
7. 방어의 300ms 판정 경로에는 원격 LLM 호출을 넣지 않는다.

## 근거 우선순위

충돌이 발생하면 다음 순서로 판단한다.

1. 본선 운영세칙과 당일 공통 운영 안내
2. `deploy/docs/agent-guide.md`의 실행 인터페이스
3. 실제 `deploy` 코드와 로컬 동작
4. 예선 보고서와 예선 소스
5. 팀이 작성한 설명 문서

본선 기술 규격은 변경될 수 있으므로 운영진이 새 안내를 제공하면 계약 테스트와 어댑터를 먼저 갱신한다.

## 저장소 경계

새 저장소 이름은 `aegis-dah2026-agents`로 한다.

포함한다.

- 공격·방어 에이전트 소스와 Dockerfile
- 본선 인터페이스 계약 테스트
- 외부 스켈레톤과 연결하는 통합 설정 및 실행 스크립트
- 예선 보고서에서 채택한 전략의 요약과 추적 문서
- CI, CODEOWNERS, 개발·운영 문서

포함하지 않는다.

- `deploy/router`, `deploy/backend`, `deploy/challenges`, `deploy/litellm-gw`
- `deploy/router/broker` 바이너리
- 원본 PDF와 예선 제출 압축물
- `tmp`, `output`, `__pycache__`, `.pyc`, PCAP, 실행 로그
- 비밀키, 제출 토큰, 실제 `.env`

## 공격 에이전트 경계

### 본선 계약

- `TARGETS`: 상대 팀 주소 CSV
- `PORTS`: 진입 포트 CSV
- `SUBMIT_URL`: 플래그 제출 URL
- `SUBMIT_TOKEN`: 팀 인증 토큰
- `LLM_BASE_URL`, `LLM_API_KEY`: 대회 LLM 프록시
- 제출 형식: `POST {SUBMIT_URL}`와 JSON `{"flag": "FLAG{...}", "token": "..."}`

### 예선 보고서에서 가져오는 것

- A1~A5 공격자 모델
- S1~S5 공격 시나리오
- 단계별 공격 체인과 관측 결과에 따른 계획 수정
- 가용성을 의식하는 공격 전략

### 새로 구현할 것

- 실제 대상 관측과 도구 실행
- 결과 정규화와 상태 저장
- 시나리오를 가설로 선택하는 계획기
- 플래그 추출·중복 제거·rate limit 대응·제출

예선의 `AttackSimulationAgent`는 합성 `CommonEvent` 생성기이므로 런타임 공격 코드로 복사하지 않는다.

## 방어 에이전트 경계

### 본선 계약

- `AGENT_SOCKET`의 `AF_UNIX`/`SOCK_SEQPACKET` 연결
- `PACKET(0x01)` 수신
- 패킷마다 300ms 안에 `VERDICT(0x02)` 반환
- `ACCEPT(0x00)` 또는 `DROP(0x01)` 결정
- 약 1초 간격 `HEARTBEAT(0x05)` 송신

### 예선 소스에서 선별 이식할 것

- `CommonEvent` 스키마의 핵심 개념
- 정규화, 시간창, 인과관계, 위험도 계산
- 결정론 판정과 AI 조언의 분리
- 다단계 공격 상관분석

### 새로 구현할 것

- Broker 통신 어댑터
- IPv4/TCP 등 원시 패킷 파서
- 패킷을 관측 가능한 이벤트로 변환하는 어댑터
- 제한된 메모리의 온라인 상관 상태
- 빠른 동기 판정 정책과 비동기 분석 경계

보고서에 나온 차량 상태, 미션 의미, 파라미터 해시 또는 물리 상태는 패킷에서 실제로 얻을 수 있을 때만 사용한다. 현재 계약이 직접 제공하지 않는 RTL·롤백·기체 제어 기능은 구현 범위에 넣지 않는다.

## 외부 스켈레톤 연동

현재 `DAH2026_스켈레톤코드/deploy`는 새 저장소 밖에 그대로 둔다. `run-with-skeleton.ps1`은 호출자가 전달한 `-SkeletonPath`를 검증하고, `integration/compose.agents.yml`을 추가 Compose 파일로 적용해 Team 1의 빌드 컨텍스트만 새 저장소의 두 에이전트로 교체한다.

절대 경로를 Git에 기록하지 않는다. 기본 경로를 추측해 파일을 복사하지 않는다. 스켈레톤이 없으면 명확한 오류와 사용법을 출력한다.

## 테스트 전략

### 단위 테스트

- 환경변수 파싱과 필수값 검증
- 플래그 추출·중복 제거·제출 응답 처리
- Broker 프레임 인코딩·디코딩
- 손상되거나 잘린 패킷에 대한 안전한 처리
- 이벤트 변환과 상관분석

### 계약 테스트

- 운영진이 정의한 환경변수 이름을 정확히 사용한다.
- 공격 제출 JSON 형식을 정확히 생성한다.
- 방어 프레임을 big-endian으로 인코딩한다.
- heartbeat와 verdict가 같은 소켓에서 안전하게 직렬화된다.
- 느린 분석 없이도 모든 패킷에 판정을 반환한다.

### 통합 테스트

- 공격·방어 이미지를 각각 독립 빌드한다.
- 외부 스켈레톤의 Team 1 서비스에 이미지를 연결한다.
- 로컬 라운드에서 플래그 제출과 verdict 로그를 확인한다.
- 에이전트 장애 시 로컬 Broker의 동작을 확인한다.

## 담당과 리뷰

- 공격 담당자: `agents/attacker/**`
- 방어 담당자: `agents/defender/**`
- 팀장 이경준: `contracts/**`, `integration/**`, 공통 문서, 전체 최종 리뷰
- 공격과 방어 Dockerfile, 계약 또는 CI 변경은 팀장 리뷰를 필수로 한다.
- 전략 문서와 구현의 연결을 PR 본문에 기록한다.
- 실제 GitHub 사용자 또는 팀 이름을 확인하기 전에는 유효하지 않은 계정을 추측해 `CODEOWNERS`를 만들지 않는다. 계정 확인 후 위 소유권 경계를 그대로 자동 리뷰 규칙에 옮긴다.

## 증빙과 보안

- 의존성 이름과 버전을 고정하고 출처를 기록한다.
- 외부 소스 또는 모델이 생성한 코드의 사용 내역을 PR과 의사결정 기록에 남긴다.
- 토큰·API 키·Registry 자격증명은 Git에 저장하지 않는다.
- 로그에는 토큰 전체나 플래그 값을 불필요하게 출력하지 않는다.

## 완료 조건

- 새 저장소가 스켈레톤 전체를 포함하지 않는다.
- 공격·방어 이미지가 독립적으로 빌드된다.
- 공격·방어의 본선 계약 테스트가 통과한다.
- 외부 스켈레톤 경로를 받아 Team 1에 두 이미지를 연결할 수 있다.
- 예선 전략과 본선 구현의 재사용·재구현 경계가 문서에 명시된다.
- 공격 담당자, 방어 담당자, 팀장의 소유권 경계가 문서화된다. GitHub 계정 확인 후 같은 경계를 CODEOWNERS에 반영한다.
