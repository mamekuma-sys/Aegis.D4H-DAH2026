# 저장소 아키텍처

## 실행 경계

```text
공격 컨테이너                         방어 컨테이너
TARGETS / PORTS                      AGENT_SOCKET
       │                                  │
       ▼                                  ▼
관측 → 계획 → 실행 → 플래그 제출       PACKET → 빠른 정책 → VERDICT
       │                                  │
       └── LiteLLM Proxy                  ├── 1초 HEARTBEAT
                                          └── 비동기 분석 경계
```

공격과 방어는 별도 이미지·컨테이너이며 런타임 상태를 공유하지 않습니다.

## 저장소와 공식 스켈레톤

이 저장소는 팀이 작성한 에이전트와 계약만 소유합니다. 공식 스켈레톤은 라우터, Broker, 백엔드, 데모 챌린지와 LiteLLM 환경을 제공하는 외부 로컬 시험장입니다. 통합 시 공식 파일을 수정하거나 복사하지 않고 Compose override로 팀 이미지의 빌드 컨텍스트만 연결합니다.

## 예선 결과물 연결

- 공격: A1~A5와 S1~S5를 정찰 가설과 계획 모델로 재설계합니다.
- 방어: CommonEvent, 시간창, 인과관계, 위험도 계산 개념을 온라인 패킷 처리에 맞게 선별 이식합니다.
- 예선 합성 점수와 탐지율을 본선 성능으로 표현하지 않습니다.
